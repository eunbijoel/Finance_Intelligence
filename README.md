# Finance Intelligence

[English README](README_EN.md)

국내 기업의 **공시·재무정보(OpenDART)** 와 사용자가 올린 **사업계획서 등 문서**를 함께 보고,  
심사역·애널리스트가 검토할 때 쓰는 **초안 메모·확인 질문·위험 신호**를 만들어 주는 AI 금융 리서치 워크벤치입니다.

> **주의:**  
> 대출 자동 승인/거절, 신용등급 부여, 한도 산정, 투자 추천 시스템이 **아닙니다**.  
> 화면의 「검토상 특이사항 없음 / 추가 확인 필요 / 중요 위험 신호 발견」도 승인·거절 뜻이 **아닙니다**.

---

## 활용 방법


| 사용자        | 이런 일에 씁니다                                   |
| ---------- | ------------------------------------------- |
| 여신·심사 담당   | 심사 건 접수 → Maker 작성 → Checker 검토·승인 프로토타입 흐름 |
| 기업 금융·리서치  | 최근 재무 변화·공시·문서 간 불일치를 한 화면에서 파악             |
| 내부 검토 워크플로 | 분석 버전·감사로그·결과 재현으로 검토 과정을 남김                  |


**권장 흐름 (심사 건 기반)**

1. 사이드바에서 **Maker** 계정 선택 (프로토타입 — 실제 로그인/SSO 아님)
2. **새 심사 건 생성** (금액·용도·상품·기한·Checker)
3. 업무함에서 건을 열고 **검토 시작**
4. 기업자료 업로드 → **AI 통합검토** → Maker 의견 작성 → Checker 검토 요청
5. **Checker** 계정으로 전환 → 원문/수정본 비교 → 수정 요청 또는 **검토 승인**
6. 「검토 승인」= **대출 승인이 아님**. 검토 메모·자료 검토 완료를 의미합니다.

기존처럼 사이드바 **기업 검색**만으로도 조회·분석할 수 있습니다 (레거시 호환).

## 예시 (권장 흐름)

API 키 없이도 **삼성전자(005930) 샘플 데이터**로 동작합니다.

```bash
cd finance_intelligence
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py --server.port 8506
```

브라우저에서 `http://localhost:8506` 을 엽니다.

1. 사이드바에서 `김심사 (MAKER)` 선택 → **새 심사 건 생성**
2. 기업명 `삼성전자`, Checker `checker01`, 금액·용도·상품·기한 입력 후 생성
3. **검토 시작** → **기업·Agent 검토**로 이동
4. **기업자료 검토**에서 `data/sample_business_plan.txt` 업로드 (SHA-256·Manifest 저장)
5. **Agent Workspace**에서 AI 통합검토 → 의견 작성 후 저장 → Checker 검토 요청
6. 사용자를 `박책임 (CHECKER)`로 바꾸고 **Checker 검토** 탭에서 승인(체크박스 3개 필수)
7. **분석·감사 이력**에서 감사로그·재현성 확인

실제 OpenDART 기업을 쓰려면 아래 [설정](#설정-env)에서 `DART_API_KEY`를 넣습니다.

## 화면별 안내

**사이드바** + **심사 업무함 / 상세 / 검토 탭**으로 구성됩니다.

### 왼쪽 사이드바


| 영역 | 하는 일 |
| ---- | ------ |
| **현재 사용자** | Maker/Checker/Admin 프로토타입 전환 (SSO 아님) |
| **심사 업무함** | 건 목록·필터·요약 카드 |
| **새 심사 건 생성** | 심사번호 `CR-YYYYMMDD-####` 자동 발급 |
| **기업·Agent 검토** | 기존 기업/문서/Agent + Checker + 감사 탭 |
| **설정·버전** | Prompt/Rule/Workflow 버전 상수 |
| **기업 검색 (레거시)** | 건 없이 기업만 조회하는 기존 방식 |
| **분석 이력 (레거시)** | case_id 없는 과거 분석도 조회 가능 |

### 심사 업무함 · Maker–Checker · 감사로그

| 기능 | 설명 |
| ---- | ---- |
| **심사 건** | `review_cases`에 저장. 상태: 접수→검토→Checker→승인/수정요청→종결 |
| **프로토타입 사용자** | maker01/02(MAKER), checker01(CHECKER), admin01(ADMIN). 동일인 Maker+Checker 불가 |
| **권한** | Maker는 승인 불가. Checker만 검토 승인·수정 요청. **실제 SSO/LDAP 아님** |
| **검토 승인** | 대출 승인 아님. AI·Maker 검토 자료의 Checker 검토 완료 |
| **문서 Manifest** | 업로드 시 SHA-256, `data/uploads/` 저장 (Git 제외) |
| **버전** | `versioning.py`의 Prompt/Rule/Workflow + 분석 시 모델·snapshot 저장 (비밀값 제외) |
| **감사로그** | 생성·상태변경·문서·분석·의견·승인·재현 — **수정·삭제 UI/API 없음** |
| **결과 재현** | REPRODUCIBLE / PARTIAL / NOT — LLM 동일 출력은 보장하지 않음 |

워크스페이스 탭: **기업 검토** · **기업자료 검토** · **Agent Workspace** · **Checker 검토** · **분석·감사 이력**

### 탭 1 — 기업 검토

“이 기업, 지금 무엇을 보고 무엇을 더 확인해야 하나?”를 **먼저** 보여주는 홈 화면입니다. 원본 재무 표 요약하여 **변화·의미·확인사항**을 위에 보여줍니다.


| 구역              | 내용                                                    |
| --------------- | ----------------------------------------------------- |
| **기업 헤더**       | 기업명, 종목코드, 업종, DART 코드, 분석 기준일, 데이터 출처(OpenDART / 샘플) |
| **바로가기 버튼**     | AI 통합검토 실행 · 기업자료 업로드 안내 · 검토보고서(Workspace) · 분석 이력   |
| **상태 카드 4개**    | 종합 검토 상태 · 중요 위험 신호 수 · 최근 공시 수 · 근거 충족도              |
| **무엇이 달라졌나**    | 최근 2개년 매출·영업이익·순이익·현금흐름·부채비율 등 변화 (규칙 기반 문장)          |
| **왜 중요한가**      | 변화·위험 규칙을 바탕으로 한 짧은 해석 (추정 없이, 확인된 패턴만)               |
| **무엇을 확인해야 하나** | 심사역이 물을 질문, 부족한 자료 (최대 5개)                            |
| **핵심 위험 신호**    | 탐지된 위험 카드 (없으면 “위험이 없다”가 아니라 **규칙상 미탐지** 안내)          |
| **재무 추이**       | 매출·영업이익·영업CF Plotly 차트                                |
| **최근 중요 공시**    | 공시명·일자·분류·DART 원문 링크 (한글 컬럼)                          |
| **원본 재무정보**     | 펼치면 억/조 단위로 읽기 쉽게 포맷된 표·재무비율                          |


**종합 검토 상태 (의미)**


| 상태          | 의미                                   |
| ----------- | ------------------------------------ |
| 분석 전        | 아직 AI 통합검토를 돌리지 않음                   |
| 검토상 특이사항 없음 | 적용된 규칙·확보 자료 기준 특이 신호 적음 → **승인 아님** |
| 추가 확인 필요    | 확인 질문·자료 보완이 필요                      |
| 중요 위험 신호 발견 | high 위험 규칙이 걸림 → **거절 아님**, 집중 검토 권고 |


---

### 탭 2 — 기업자료 검토

사업계획서·설명자료 등에서 **여신 검토에 필요한 항목**을 뽑고, 가능한 한 **근거 위치**를 남깁니다.

**(지원 형식:** PDF, DOCX, XLSX, CSV, TXT)

**추출 항목 예:**

- 기업 개요, 사업 목적, 자금 사용 목적  
- 매출·비용 전망, 상환 계획  
- 주요 거래처, 핵심 기술·사업 역량, 위험요인  
- 문서에서 **확인되지 않은 항목**

**근거:** 파일명, 페이지/시트, 셀·위치(알 수 없으면 “위치 확인 불가”), 원문 일부  
**여러 파일:** 같은 항목이 문서마다 다르면 **덮어쓰지 않고 모두 보존** → 이후 교차검증에서 불일치로 표시될 수 있습니다.

샘플 문서: `data/sample_business_plan.txt`

---

### 탭 3 — Agent Workspace

**역할:** DART 재무 + 업로드 문서를 묶어서 **단계적으로** 분석하고, 검토 메모·교차검증·근거 검증을 보여 줍니다.

**실행:** 「AI 통합검토 실행」 (기업 검토 탭의 같은 버튼과 동일 워크플로)

**Agent 단계 (대략)**

1. 입력 확인 → 2. DART 수집 → 3. 문서 분석 → 4. 재무비율 계산
2. 교차검증 → 6. 위험 탐지 → 7. 근거 검증 → 8. 메모 초안
3. 사용자 검토 → 10. 승인·저장

근거가 부족하면 결론을 억지로 내지 않고 `**NEEDS_MORE_INFORMATION**` 으로 멈추고, 부족한 자료·질문을 보여 줍니다.


| 항목            | 설명                                         |
| ------------- | ------------------------------------------ |
| 종합 상태·핵심 요약   | 초안 메모 (Ollama 연결 시 서술 보강, 없으면 규칙 기반 요약)    |
| 위험 신호         | 심각도(high/medium) + 설명 + 근거 수치 + 검토 질문      |
| 교차검증          | 사업계획 매출 vs 공시, 문서 간 수치 불일치, 자금용도·상환계획 유무 등 |
| 근거 검증         | 주장별 supported / partial / unsupported      |
| Markdown 다운로드 | 기업명_기업검토_날짜.md 형식 보고서                      |
| 승인 후 저장       | SQLite에 저장 → 사이드바 분석 이력에 등장                |

## 주요 기능 상세

### 재무·비율 (Python 계산)

매출·영업이익·순이익·자산·부채·자본·영업CF 및  
부채비율, 유동비율, 영업이익률, 순이익률, ROA, ROE, 영업CF/단기차입 등.  
데이터 없으면 **추정하지 않고** 「계산 불가 + 사유」.

### 위험 신호 (명시적 규칙)

예: 영업CF 2년 연속 음수, 부채비율 급증, 유동비율 하락, 매출↑·이익/CF↓,  
단기차입 급증, 매출채권 증가율 ≫ 매출 증가율, 사업계획 과도 낙관,  
공시와 계획 수치 불일치, 상환·자금용도 미기재 등.  

임계값은 `config.py`의 `RISK_THRESHOLDS`에서 수정합니다.

### 교차검증

문서에서 억/조 등 단위를 구분해 수치를 뽑을 수 있을 때만 비교합니다.  
기준연도가 다르면 “불일치”로 단정하지 않고 **기준연도 확인 필요**로 표시합니다.

### Decision Memory (분석 이력)

승인·저장 시 기업·날짜·문서·비율·위험·메모·근거·수정 내용이 SQLite에 남습니다.  
같은 기업을 다시 분석하면 신규/해소된 위험, 비율 악화·개선, 공시·메모 차이 힌트를 보여 줄 수 있습니다.

### LLM (선택)

기본은 **로컬 Ollama** `gemma4:31b`. API 키 불필요.  
Ollama가 꺼져 있어도 **규칙 기반 분석은 그대로** 동작하고, 문장 서술만 약해집니다.

## 설정 (`.env`)

프로젝트 루트에 `.env`를 **직접** 만드세요. Git에 올리지 않습니다 (`.gitignore`).


| 변수                             | 설명                                             |
| ------------------------------ | ---------------------------------------------- |
| `DART_API_KEY`                 | [OpenDART](https://opendart.fss.or.kr/) API 키  |
| `LLM_PROVIDER`                 | `ollama`(기본) 또는 `openai`                       |
| `OLLAMA_BASE_URL`              | Ollama 주소                                      |
| `LLM_MODEL`                    | 모델명 (기본 `gemma4:31b`)                          |
| `LLM_BASE_URL` / `LLM_API_KEY` | `LLM_PROVIDER=openai`일 때만                      |
| `FI_MOCK_LLM`                  | `true`면 LLM 호출 안 함                             |
| `FI_DB_PATH`                   | SQLite 경로 (비우면 `data/finance_intelligence.db`) |

## 알아두면 좋은 한계 (MVP)

- 공시 **본문 PDF 자동 정밀 파싱**은 범위 밖 (목록·링크 중심)
- Excel/DOCX 보고서 내보내기는 TODO (Markdown은 지원)
- LLM은 **숫자를 새로 만들지 않도록** 프롬프트되어 있으나, 최종 판단은 항상 사람이 합니다
- 사용자 선택은 **프로토타입**입니다. SSO, LDAP, 전자결재, 은행 내부망 연동은 없습니다
- 결과 재현은 입력·버전·문서 해시 복원/비교 중심이며, LLM 텍스트 동일성을 보장하지 않습니다
